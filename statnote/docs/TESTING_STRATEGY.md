# Стратегия тестирования

## Пирамида

| Уровень | Инструмент | Что проверяет |
|---|---|---|
| Модульные | xUnit | логика узлов AST, типов, резолвера |
| Golden | xUnit плюс эталоны | AST, генерируемый C#, графы зависимостей |
| Аллокационные | BenchmarkDotNet | отсутствие промежуточных массивов при fusion |
| Интеграционные | xUnit с флагом среды | R, Python, Julia, DLL |
| Представление | снапшоты | PDF, HTML, PPTX |
| UI | ViewModel-тесты | режимы отображения без потери состояния |
| Сквозные | примеры .smd | полный цикл документа |
| Автономность | чистое окружение | AOT-файл без установленного runtime |

## Golden-тесты как память проекта

Эталоны хранятся в `tests/golden/`. Обновление эталона — отдельный коммит
с обоснованием в сообщении и ссылкой на ADR, если менялась семантика.
При расхождении мнения разработчика и эталона доверяют эталону.

Минимальный набор F1: тридцать конструкций языка, каждая в русском и английском
варианте, с проверкой идентичности деревьев.

## Интеграционные тесты

По умолчанию выполняются только mock-тесты преобразования типов. Реальные среды
включаются флагом `STATNOTE_INTEGRATION=1` и отдельным заданием CI, чтобы
отсутствие R на агенте не ломало сборку.

## Детерминизм

Отдельный тест: два независимых restore дают побитово идентичный замок.
Отдельный тест: пакетный прогон документа совпадает с интерактивным по всем
числовым результатам и подписям.

## Покрытие

Цель — не менее 80 процентов логики на модуль. Покрытие измеряется в CI
и заносится в `MODULE_STATUS.md`.

## Регрессии

Запрещено переходить к следующему модулю при красных тестах смежных модулей.
Исключение фиксируется в `DECISIONS.md` с планом погашения долга.

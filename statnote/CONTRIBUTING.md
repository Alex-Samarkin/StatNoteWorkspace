# Порядок работы над StatNote

## Правило непрерывности

Контекст живит в репозитории, а не в переписке. Каждая сессия начинается с чтения
контекстного пакета и заканчивается его обновлением.

## Контекстный пакет

1. `docs/03_ai_prompt.md` — целиком.
2. `docs/PROJECT_CONTEXT.md` — актуальный.
3. `docs/MODULE_STATUS.md` — актуальный.
4. Выписка из ТЗ или файл `docs/SPEC/` по текущему модулю.
5. Последний снимок `docs/context_bundles/cb_*.md`.
6. Интерфейсы смежных модулей (не реализации).

Не подавайте весь код проекта — только контракты.

## Протокол сессии

- **Вход:** прочитать пакет, сверить цель с `MODULE_STATUS`.
- **План:** не более 10 пунктов, явные критерии готовности.
- **Работа:** тесты, реализация, прогон, исправление. Один модуль за сессию.
- **Выход:** обновить `MODULE_STATUS` и `PROJECT_CONTEXT`, записать ADR при развилках,
  выдать сводку не более 30 строк.

## Коммиты

Формат: `[M4] transpiler: vector fusion without intermediate arrays`.

## Запреты

- Менять девять неизменных архитектурных решений без ADR с пометкой BREAKING.
- Добавлять зависимости без записи в `DECISIONS.md` и проверки лицензии.
- Оставлять заглушки без пометки TODO с номером модуля.
- Начинать модуль, не закрыв врата предыдущего.

## Тесты

См. `docs/TESTING_STRATEGY.md`. Golden-тесты — эталон семантики; при расхождении
мнения и golden доверяйте golden.

# Программа разработки StatNote с сохранением контекста

## 1. Принцип непрерывности

Контекст проекта хранится **в репозитории, а не в головах и не в чатах**. Каждая сессия
(человека или ИИ) начинается с чтения канонических артефактов и заканчивается их
обновлением. Новый этап никогда не стартует с нуля: он стартует с «контекстного пакета»
предыдущего.

## 2. Канонические артефакты (живут в git)

```
statnote/
├── docs/
│   ├── PROJECT_CONTEXT.md      # Единый источник истины: что решено, что готово
│   ├── DECISIONS.md            # ADR-журнал: решение, обоснование, альтернативы
│   ├── MODULE_STATUS.md        # Матрица M0–M14: статус, покрытие, ограничения
│   ├── SDK_CONTRACTS.md        # Интерфейсы и атрибуты Sdk (контракты для ИИ)
│   ├── SPEC/
│   │   ├── grammar.ebnf
│   │   ├── packages.md         # Схема StatNote.toml, lock, реестр, MVS
│   │   └── *.lang
│   └── context_bundles/        # Снимки контекста по этапам
├── src/
│   ├── StatNote.Sdk/           # Публичные контракты (NuGet для авторов пакетов)
│   ├── StatNote.Package/       # Менеджер пакетов
│   ├── StatNote.TestKit/       # Тестовый SDK
│   ├── StatNote.Registry/      # Инструменты реестра
│   └── ...                     # Core, Parser, Transpiler, Compiler, Runtime, Export, UI, Cli
├── packages/                   # Локальные пакеты рабочей области
├── vendor/                     # Офлайн-копии исходников (опционально)
├── statnote.lock
├── tests/
│   ├── golden/                 # Эталонные AST, C#-выходы, графы резолвера
│   └── end_to_end/             # Сквозные документы .smd
└── .github/workflows/          # CI: build, test, golden, examples
registry/                       # Отдельный git-репозиторий метаданных
```

**PROJECT_CONTEXT.md** содержит: текущую фазу; принятые неизменные решения (9 пунктов
из промпта); статус модулей; открытые вопросы; следующий шаг. Объём — не более 2 страниц,
обновляется каждую сессию.

**DECISIONS.md** — формат ADR: `Дата | Решение | Обоснование | Отвергнутые альтернативы |
Последствия`. Обязательные стартовые записи ADR-01…ADR-16 (см. раздел 10).

## 3. Фазы и врата

| Фаза | Модули | Врата выхода (все обязательны) | Снимок |
|------|--------|-------------------------------|--------|
| **F1. Фундамент** | M0–M2 | CI зелёный; golden-AST для 30 конструкций; ru эквивалентен en; схема манифеста зафиксирована | cb_f1.md |
| **F2. Семантика и генерация** | M3–M4 | FR-V тесты 100%; fusion-аллокационные тесты; golden C# | cb_f2.md |
| **F3. Исполнение и SDK** | M5, M6, M12 | Сквозной 5-ячеечный документ; реактивный пересчёт; изоляция ошибок; регистрация SDK-функций; TestKit зелёный | cb_f3.md |
| **F4. Интеграция и пакеты** | M7, M13 | R end-to-end (survfit); marshalling-тесты; MVS/lock/hash/vendor/ALC тесты; мультипакет исполняется | cb_f4.md |
| **F5. Представление** | M8–M9 | PDF/HTML/PPTX снапшоты; 5 вкладок; режимы без потери состояния | cb_f5.md |
| **F6. Автономность и экосистема** | M10, M11, M14 | AOT с пакетами на чистом окружении; пакетный прогон идентичен интерактивному; примеры в CI; publish dry-run; yank; зеркало | cb_f6.md |

**Правило врат:** переход к следующей фазе запрещён, пока все врата текущей не зелёные
в CI. Исключения фиксируются в DECISIONS.md с планом погашения долга.

## 4. Контекстный пакет (что подавать ИИ на каждой сессии)

1. `03_ai_prompt.md` (мастер-промпт, целиком).
2. `PROJECT_CONTEXT.md` (актуальный).
3. `MODULE_STATUS.md` (актуальный).
4. Выписка из `02_specification.md` — только разделы текущего модуля.
5. Последний `context_bundles/cb_*.md`.
6. Интерфейсы (не реализации) смежных модулей.
7. `SDK_CONTRACTS.md` — при работе с M5, M6, M12–M14.
8. `SPEC/packages.md` — при работе с M12–M14.
9. Эталонные графы зависимостей из `tests/golden/resolver/` — при работе с M13–M14.

Правило: **не подавать весь код проекта** — только контракты.

## 5. Протокол сессии (обязателен для человека и ИИ)

```
ВХОД:    прочитать контекстный пакет, сверить цель сессии с MODULE_STATUS
ПЛАН:    не более 10 пунктов, явные критерии готовности
РАБОТА:  тесты, реализация, прогон, исправление (только текущий модуль)
ВЫХОД:   обновить MODULE_STATUS и PROJECT_CONTEXT
         записать ADR при развилках
         выдать сводку не более 30 строк: сделано / ограничения / следующий шаг
         commit с тегом модуля: [M4] transpiler: vector fusion
```

## 6. Защита от потери контекста

- **Снимки фаз:** при закрытии врат — `cb_fN.md` (решения, статус, граф зависимостей
  модулей, известные проблемы). Это «точка сохранения».
- **Golden-тесты как память:** эталонные AST, C#-выходы и графы резолвера фиксируют
  семантику лучше прозы; при расхождении доверять golden.
- **Запрет молчаливого пересмотра:** любое изменение принятых решений — только через ADR
  с пометкой BREAKING и обновлением всех четырёх документов.
- **Двойная документация решений:** краткая в PROJECT_CONTEXT (для быстрого входа) плюс
  полная в DECISIONS (для археологии).
- **Еженедельная ревизия:** PROJECT_CONTEXT перечитывается целиком; устаревшие пункты
  удаляются, чтобы документ не разрастался.

## 7. Реестр рисков

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| Дрейф архитектуры между ИИ-сессиями | Высокая | Неизменные решения в промпте; ADR-обязательство; golden-тесты |
| Fusion не даёт выигрыша | Средняя | Аллокационные бенчмарки на F2; fallback на явные циклы |
| Сложность marshalling R/Python | Высокая | Начать с Arrow и примитивов; сложные типы итеративно; mock-тесты первыми |
| Цепочка поставок пакетов | Высокая | Подписанный реестр, checksum-журнал, `pkg audit`, yank; запрет непроверенных источников по умолчанию |
| Холодная сборка пакетов медленная | Средняя | Кэш по хешам; параллельная сборка; NFR-08/10 в CI |
| Ломающие изменения SDK | Средняя | Версия `sdk` в манифесте; мажорные `/v2`; ADR BREAKING |
| Управление реестром | Средняя | Курирование через PR; приватные зеркала; регламент в `SPEC/packages.md` |
| Лицензии исходных пакетов | Средняя | `pkg audit` обязателен перед publish; отчёт в реестре |
| Раздувание UI-модуля | Средняя | M9 строго после F3; ViewModel-тесты; режимы через единый enum состояния |
| Горизонт .NET 10 LTS (3 года) | Низкая | Абстракция Compiler-слоя; план миграции на следующий LTS в F6 |

## 8. Метрики здоровья проекта

- Процент зелёных врат по фазам (цель: 100 перед переходом).
- Покрытие тестами логики (цель: не менее 80% на модуль).
- Время компиляции ячейки (NFR-01, регрессионный бенчмарк в CI).
- Время холодной сборки пакета и тёплой загрузки (NFR-08, NFR-10).
- Доля пакетов с TestKit-тестами (цель: 100% в реестре).
- Детерминизм restore (цель: 100% побитовых совпадений lock в CI).
- Число открытых ADR-вопросов (цель: не более 3).
- Возраст последнего обновления PROJECT_CONTEXT (цель: не более 1 сессии).

## 9. Стартовый чек-лист (день 1)

1. Создать репозиторий, папку `docs/`, четыре документа концепции.
2. Заполнить PROJECT_CONTEXT.md начальными решениями (9 пунктов).
3. Записать ADR-01…ADR-16 (раздел 10).
4. Выполнить M0: скелет solution и CI.
5. Создать проекты `StatNote.Sdk`, `StatNote.Package`, `StatNote.TestKit`,
   `StatNote.Registry`.
6. Зафиксировать схему `StatNote.toml` и `statnote.lock` в `SPEC/packages.md`.
7. Подготовить эталонные графы резолвера (простой, diamond, `/v2`, yank).
8. Подать ИИ контекстный пакет с целью «M1: Core AST и типы».

| 04 | Разделение доступа: `.` статика, `$` динамика |

# Техническое задание: язык и среда StatNote

## 1. Общие сведения

| Пункт | Содержание |
|---|---|
| Название | StatNote (рабочее) |
| Назначение | Язык статистических вычислений и среда литерного программирования |
| Целевая аудитория | Исследователи, преподаватели, студенты (медицина, биология, соц. науки) |
| Платформа исполнения | .NET 10 (LTS), транспиляция в C# |
| Целевые ОС | Windows 10/11 x64, Linux x64 (включая Manjaro), macOS (опционально) |
| Формат документа | `.smd` (текстовый, UTF-8) |
| Форматы экспорта | PDF, HTML, PPTX; полный отчёт с кодом |

## 2. Цели и границы

**Цели:** интерактивный анализ данных; генерация документов типографского качества;
воспроизводимость; интеграция с R/Python/Julia/DLL; нативное расширение пакетами на C#;
билингвальный синтаксис.

**Вне границ первой версии:** собственная VM/компилятор в машинный код; GPU-вычисления;
облачная совместная работа; мобильные платформы; расширение грамматики пакетами.

## 3. Требования к языку

### 3.1. Лексика и синтаксис (FR-L)

| ID | Требование |
|---|---|
| FR-L01 | Блоки `{ }`; завершение `;` опционально; комментарии `//`, `/* */` |
| FR-L02 | Присваивание: `<-` (основное), `->` (обратное, для конвейеров) |
| FR-L03 | Глобальное присваивание: `global x <- v`, `x <<- v`, `v ->> x` |
| FR-L04 | Конвейер `\|>`; именованные аргументы через `:`; интерполяция `$"{expr}"` |
| FR-L05 | Формулы `y ~ x1 + x2`; null-безопасный доступ `?.` |
| FR-L06 | Атрибуты `[Имя(аргументы)]` для ячеек, классов, членов |
| FR-L07 | Объявления: `class`, `function`, стрелочные функции `=>`, лямбды |

### 3.2. Семантика переменных (FR-V) — критический раздел

| ID | Требование |
|---|---|
| FR-V01 | **Переменные локальны по умолчанию** (область — текущая ячейка) |
| FR-V02 | Глобальные объявляются: `global`, атрибут `[Экспорт(...)]`, оператор `<<-` |
| FR-V03 | Локальная переменная затеняет глобальную; выдаётся предупреждение SN001 |
| FR-V04 | Квалификатор `global::x` — явный доступ к глобальной при затенении |
| FR-V05 | Директива `@strict_shadowing true` — затенение становится ошибкой |
| FR-V06 | Режим `@variable_scope r_style` — глобальные по умолчанию (совместимость) |
| FR-V07 | Чтение неразрешённого имени — ошибка компиляции с указанием ячейки/строки |
| FR-V08 | Циклические зависимости ячеек — ошибка на этапе анализа |

### 3.3. Классы и объекты (FR-C)

| ID | Требование |
|---|---|
| FR-C01 | Классы: поля, свойства (get/set), методы, конструкторы, наследование |
| FR-C02 | Доступ `.` — только к объявленным членам; неизвестное поле — ошибка |
| FR-C03 | Доступ `$` — к динамическому словарю экземпляра; создание на лету |
| FR-C04 | Динамическое поле не может перезаписать статическое (ошибка с подсказкой) |
| FR-C05 | Интроспекция: `inspect`, `fields`, `static_fields`, `dynamic_fields`, `methods`, `has_field`, `field_type` |
| FR-C06 | Режимы класса `[Strict]` / `[Dynamic]` (запрет/разрешение динамики) |
| FR-C07 | Векторизованный доступ к полям коллекций: `patients.age`, `patients$group` |

### 3.4. Векторизация (FR-B)

| ID | Требование |
|---|---|
| FR-B01 | Broadcast функций `f.(x)` и операторов `x .+ y`, `x .* 2` |
| FR-B02 | Расширение размерностей по правилам broadcasting (скаляр/вектор/матрица) |
| FR-B03 | **Fusion**: цепочка точечных операций — один цикл без промежуточных массивов |
| FR-B04 | Директива `@.` для broadcast всего выражения |
| FR-B05 | Однозначный разбор: `obj.field` (доступ) vs `f.(x)` (broadcast) vs `x .+ y` |
| FR-B06 | SIMD-ускорение через `Tensor<T>`/`Vector<T>` при наличии поддержки |
| FR-B07 | Fusion допускается через границы пакетов только для функций `[StatPure]` |

### 3.5. Типы и данные (FR-T)

| ID | Требование |
|---|---|
| FR-T01 | Постепенная типизация: вывод типов плюс явные аннотации; `var` |
| FR-T02 | Базовые типы: int, double, string, bool, list, dict, matrix, dataframe, factor |
| FR-T03 | Встроенная семантика NA с трёхзначной логикой; отдельный NaN |
| FR-T04 | Factor — самостоятельный тип с уровнями и порядком |
| FR-T05 | DataFrame — колоночное хранение (Apache Arrow), zero-copy срезы |
| FR-T06 | Запрет неявного приведения string в number и подобных |

### 3.6. Билингвальность (FR-I18N)

| ID | Требование |
|---|---|
| FR-I18N01 | `@language ru \| en \| ru, en` в преамбуле, до любого кода |
| FR-I18N02 | Словари ключевых слов и типов в YAML (`.lang`), расширяемые |
| FR-I18N03 | Локализация ошибок, предупреждений, справки |
| FR-I18N04 | Идентификаторы не зависят от директивы языка; Unicode-имена допустимы |

## 4. Требования к документу и среде

### 4.1. Структура документа (FR-D)

| ID | Требование |
|---|---|
| FR-D01 | Невидимая преамбула: `@language`, `@configure`, `@packages`, `using`, настройки, данные |
| FR-D02 | Невидимый подвал: функции, классы, константы; без побочных эффектов |
| FR-D03 | Ячейки Markdown (с интерполяцией `{expr}`) и расчётные |
| FR-D04 | Порядок исполнения: преамбула, подвал, ячейки сверху вниз |
| FR-D05 | Реактивность: изменение ячейки инвалидирует зависимые (граф reads/writes) |
| FR-D06 | Пакетный режим: чистое окружение, детерминированный прогон сверху вниз |

### 4.2. Интерфейс (FR-UI)

| ID | Требование |
|---|---|
| FR-UI01 | Пять вкладок: Преамбула, Текст, Подвал, Инспектор данных, Модули |
| FR-UI02 | Режимы ячейки: раздельные вкладки; рядом (лево/право/верх/низ); visible/hide_code/hide_output/hide_both |
| FR-UI03 | Инспектор: переменные, типы, размеры, структура объектов, быстрые статистики, мини-распределения |
| FR-UI04 | Модули: статус внешних сред и пакетов, версии, установка, конфликты, замок, аудит доверия |
| FR-UI05 | Панель состояния, оглавление, статусы ячеек (выполнено/устарело/ошибка), горячие клавиши режимов |

### 4.3. Экспорт (FR-E)

| ID | Требование |
|---|---|
| FR-E01 | PDF типографского качества (QuestPDF или Typst-бэкенд); формулы LaTeX; векторные графики |
| FR-E02 | HTML: семантика, MathML, интерактивные SVG-графики |
| FR-E03 | PPTX: заголовки в слайды, автокомпоновка графиков/таблиц (OpenXML) |

| FR-E05 | Видимость ячеек соблюдается при экспорте; преамбула и подвал не экспортируются |

## 5. Внешняя интеграция (FR-X)

| ID | Требование |
|---|---|
| FR-X01 | `using Module from r\|python\|julia\|dll\|csharp\|lua\|package("путь")` |
| FR-X02 | Блок `@configure` в преамбуле: пути, версии, репозитории, venv, потоки, опции, зеркала реестра |
| FR-X03 | Автопоиск сред (env vars, стандартные пути, PATH, conda/venv); понятная ошибка при отсутствии |
| FR-X04 | Ленивая инициализация runtime; профили конфигурации (development/production) |
| FR-X05 | Marshalling: NA/NA/None/missing; factor/Categorical; формулы в R; DataFrame через Arrow (zero-copy) |
| FR-X06 | Трансляция исключений внешних сред в типизированные ошибки с трассировкой |
| FR-X07 | Манифест зависимостей с фиксацией версий и хешей DLL |

## 5а. Нативные расширения и пакеты

### 5а.1. SDK нативных расширений (FR-NX)

| ID | Требование |
|---|---|
| FR-NX01 | Публичный пакет `StatNote.Sdk`: атрибуты `[StatModule]`, `[StatFunction]`, `[StatType]`, `[StatCellAttribute]`, `[StatDoc]`, `[StatPure]`; интерфейсы `IStatModule`, `IModuleRegistry` |
| FR-NX02 | Регистрация функций/типов в билингвальных таблицах символов через `Name`/`RuName`; справка из `[StatDoc]` доступна в `?help` |
| FR-NX03 | Сигнатуры SDK: `Tensor<T>`, `Span<T>`, `DataFrame`, `Factor`, `Missing`; политика NA задаётся параметром `MissingPolicy` |
| FR-NX04 | `[StatPure]` разрешает участие функции в fusion; отсутствие атрибута — барьер сплавления |
| FR-NX05 | Интроспекция происхождения: `origin(fn)` — путь пакета, версия, файл исходника, хеш |
| FR-NX06 | Загрузка пакета в коллектируемый `AssemblyLoadContext`; контракты SDK в общем контексте; выгрузка и перезагрузка без перезапуска среды |
| FR-NX07 | Совместимость: манифест объявляет версию `sdk`; runtime отклоняет несовместимые мажорные версии |
| FR-NX08 | Опционально: блоки `[Native(csharp)]` в подвале документа для прототипирования; в пакетах не допускаются |
| FR-NX09 | `StatNote.TestKit`: golden-тесты функций, NA-пропагация, broadcast-корректность, проверка чистоты |

### 5а.2. Пакеты и менеджер (FR-P)

| ID | Требование |
|---|---|
| FR-P01 | Манифест `StatNote.toml`: путь, UUID, версия, `kind`, `sdk`, лицензия, зависимости, экспорт |
| FR-P02 | `kind = "library"` — код в `src/`; `kind = "meta"` — только `[dependencies]` и `[exports]`, кода нет |
| FR-P03 | Идентичность: модульный путь плюс UUID; мажорные версии — отдельный путь `.../pkg/v2` |
| FR-P04 | **Source-first**: распространение исходниками; бинарные пакеты — исключение с пометкой `binary` и проверкой trim-совместимости |
| FR-P05 | Разрешение версий MVS; замок `statnote.lock` с точными версиями и контентными хешами |
| FR-P06 | Реестр: git-репозиторий метаданных (`Package.toml`, `Versions.toml`); регистрация через PR |
| FR-P07 | Proxy-кэш (`/@v/list`, `/@v/<ver>.zip`, `/@v/<ver>.toml`) и журнал контрольных сумм; верификация при restore |
| FR-P08 | Приватные зеркала реестра для организаций; переключение через `@configure` |
| FR-P09 | CLI: `statnote pkg init/add/restore/build/test/update/why/graph/vendor/publish/audit` |
| FR-P10 | Кэш сборок по ключу (хеш исходников, версия SDK, TFM, RID); холодная сборка типичного пакета не более 3 с |
| FR-P11 | `vendor/` — офлайн-копия исходников; restore без сети при наличии vendor |
| FR-P12 | Подключение в преамбуле: блок `@packages` с версиями; `using X from package("путь")`; мультипакет реэкспортирует `[exports]` |
| FR-P13 | Отзыв версии (`yank`) скрывает её из разрешения, но не удаляет; замок продолжает работать |
| FR-P14 | `pkg audit`: лицензии, статический анализ опасных API, отчёт доверия |

### 5а.3. Примеры (нормативные)

```toml
# StatNote.toml — library
[package]
name = "statnote.org/med/survival"
uuid = "b7e2..."
version = "1.4.2"
kind = "library"
sdk = "1.0"
license = "MIT"

[dependencies]
"statnote.org/core/stats" = "1.2"
```

```toml
# StatNote.toml — meta
[package]
name = "statnote.org/med/bundle"
version = "2026.11"
kind = "meta"

[dependencies]
"statnote.org/med/survival" = "1.4"
"statnote.org/med/pk"       = "0.9"

[exports]
namespaces = ["StatNote.Med.Survival", "StatNote.Med.PK"]
```

```csharp
[Преамбула]
{
    @packages { "statnote.org/med/bundle" = "2026.11"; }
    using Medical from package("statnote.org/med/bundle");
    using survival from r;   // внешняя среда — как прежде
}
```

| ID | Требование |
|---|---|
| FR-R01 | Транспиляция AST в C#; исполнение на .NET 10 |
| FR-R02 | Roslyn: инкрементальная компиляция ячеек, кэш сборок |
| FR-R03 | Контекст: типизированный `Globals` плюс `ExecutionScope` (locals), передача по ссылке для объектов |
| FR-R04 | DependencyAnalyzer по AST: reads/writes/locals; топологический порядок; детекция циклов |
| FR-R05 | Реактивный кэш (HybridCache) с инвалидацией по тегам переменных |
| FR-R06 | NativeAOT: пакетная сборка документа в автономный исполняемый файл |
| FR-R07 | Source maps: ошибки исполнения сопоставляются с исходными ячейками и строками |
| FR-R08 | Исходники пакетов включаются в компиляцию документа; cross-package fusion для `[StatPure]` |
| FR-R09 | NativeAOT-сборка включает исходники пакетов; бинарные зависимости помечаются как trim-риск |
| FR-R10 | Source maps распространяются на исходники пакетов |

## 7. Нефункциональные требования (NFR)

| ID | Требование | Целевое значение |
|---|---|---|
| NFR-01 | Компиляция одной ячейки | не более 300 мс (типичная ячейка, тёплый кэш) |
| NFR-02 | Векторные операции | не медленнее 2x к эквивалентному ручному циклу C# |
| NFR-03 | Передача DataFrame между ячейками | zero-copy, не более 1 мкс overhead |
| NFR-04 | Запуск AOT-документа | не более 200 мс до первой ячейки |
| NFR-05 | Надёжность | падение ячейки не роняет среду; состояние изолировано |
| NFR-06 | Локализация | ru/en для интерфейса, ошибок, справки |
| NFR-07 | Лицензии | аудит лицензий зависимостей (QuestPDF, R, Python, пакеты) |
| NFR-08 | Тёплая загрузка пакета из кэша | не более 50 мс |
| NFR-09 | Детерминизм restore | побитово идентичный `statnote.lock` при тех же манифестах |
| NFR-10 | Офлайн-исполнение | возможно при наличии `vendor/` и кэша сборок |

## 8. Критерии приёмки (верхний уровень)

1. Документ с преамбулой, подвалом и ячейками исполняется интерактивно и пакетно, давая идентичные результаты.
2. Семантика FR-V01–V08 проходит полный набор тестов, включая затенение и `global::`.
3. Класс с раздельной интроспекцией `.` и `$` работает по FR-C.
4. Broadcast с fusion подтверждён тестом отсутствия промежуточных аллокаций.
5. Билингвальный документ (ru и en варианты) даёт идентичный AST.
6. Вызов R-функции (`survival::survfit`) с передачей DataFrame и возвратом результата работает end-to-end.
7. Экспорт PDF/HTML/PPTX из одного документа с учётом видимости ячеек.
8. AOT-сборка запускается на машине без .NET runtime.
9. Документ с мультипакетом разрешается, собирается и исполняется; версии зафиксированы в замке.
10. Функция пакета вызывается под ru- и en-именами; `origin()` возвращает происхождение.
11. Fusion через границу пакета подтверждён аллокационным тестом для `[StatPure]`.
12. AOT-файл включает пакет и запускается на чистом окружении.
13. Несовпадение контрольной суммы при restore прерывает операцию с понятной ошибкой.

## 9. Технологический стек (обязательный)

C# / .NET 10; ANTLR4 (парсер); Roslyn (компиляция); System.Numerics.Tensors и SIMD;
Microsoft.Extensions.Caching.Hybrid; Apache Arrow; Avalonia (UI); QuestPDF или Typst,
OpenXML SDK (экспорт); R.NET, Python.NET, Julia-interop; xUnit и BenchmarkDotNet (тесты);
Tomlyn (TOML); LibGit2Sharp (git); коллектируемые `AssemblyLoadContext`.

Проекты расширения: `StatNote.Sdk` (публичные контракты, NuGet), `StatNote.Package`
(менеджер), `StatNote.TestKit` (тестовый SDK), `StatNote.Registry` (инструменты реестра).

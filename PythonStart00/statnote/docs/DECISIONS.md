# DECISIONS — журнал архитектурных решений

Формат: дата, решение, обоснование, отвергнутые альтернативы, последствия.
Изменение принятого решения допускается только через новую запись с пометкой BREAKING.

## ADR-01 — Транспиляция в C# вместо собственного компилятора
Дата: 2026-11-18. Обоснование: снимает годы работы над runtime, даёт готовую экосистему.
Альтернативы: собственный байт-код и JIT; транспиляция в Go; чистый интерпретатор.
Последствия: зависимость от .NET; source maps обязательны.

## ADR-02 — Платформа .NET 10 (LTS)
Дата: 2026-11-18. Обоснование: долгосрочная поддержка, тензоры, SIMD, NativeAOT.
Альтернативы: .NET 9 (STS), .NET 8 (LTS истекает).
Последствия: горизонт поддержки три года; план миграции на следующий LTS в F6.

## ADR-03 — Переменные локальны по умолчанию
Дата: 2026-11-18. Обоснование: устраняет скрытые зависимости между ячейками.
Альтернативы: глобальные по умолчанию как в R.
Последствия: требуется явный экспорт; режим совместимости `r_style`.

## ADR-04 — Разделение доступа: точка и доллар
Дата: 2026-11-18. Обоснование: семантическая ясность, ранняя проверка опечаток, скорость.
Альтернативы: единый доступ через точку.
Последствия: два уровня интроспекции; запрет перезаписи статики динамикой.

## ADR-05 — Broadcast в стиле Julia с fusion
Дата: 2026-11-18. Обоснование: читаемость формул при производительности цикла.
Альтернативы: неявная векторизация как в R; явные циклы.
Последствия: нужен аллокационный контроль в тестах.

## ADR-06 — Билингвальность через словари
Дата: 2026-11-18. Обоснование: русскоязычное обучение без потери международной совместимости.
Альтернативы: только английский; жёсткая локализация в грамматике.
Последствия: словари `.lang`; эквивалентность AST проверяется golden-тестами.

## ADR-07 — Невидимые преамбула и подвал
Дата: 2026-11-18. Обоснование: чистота итогового документа при полной инфраструктуре.
Альтернативы: видимые служебные ячейки; внешние конфигурационные файлы.
Последствия: порядок исполнения фиксирован; подвал без побочных эффектов.

## ADR-08 — Реактивность через граф зависимостей и HybridCache
Дата: 2026-11-18. Обоснование: пересчёт только затронутых ячеек.
Альтернативы: полный прогон при каждом изменении; ручной запуск.
Последствия: обязателен анализ reads/writes и детекция циклов.

## ADR-09 — Нативные пакеты на C# в исходных кодах
Дата: 2026-11-18. Обоснование: научная проверяемость, cross-package fusion, NativeAOT.
Альтернативы: бинарные плагины; расширения на собственном языке.
Последствия: нужен SDK, кэш сборок, аудит доверия.

## ADR-10 — Виды пакетов: library и meta
Дата: 2026-11-18. Обоснование: предметные и учебные комплекты без дублирования кода.
Альтернативы: только библиотеки; профили конфигурации вместо мультипакетов.
Последствия: манифест meta содержит зависимости и exports, но не код.

## ADR-11 — Идентичность: путь плюс UUID, мажорные версии в пути
Дата: 2026-11-18. Обоснование: защита от переименований и конфликтов версий.
Альтернативы: плоские имена; SemVer-диапазоны без разделения путей.
Последствия: `/v2` — отдельный модуль; реестр хранит UUID.

## ADR-12 — Разрешение версий MVS плюс замок с хешами
Дата: 2026-11-18. Обоснование: детерминизм вместо SAT-разрешения.
Альтернативы: резолвер Julia; новейшая совместимая версия.
Последствия: побитовая воспроизводимость `statnote.lock`.

## ADR-13 — Реестр: git-метаданные, proxy, журнал сумм
Дата: 2026-11-18. Обоснование: курирование как в Julia, офлайн как в Go.
Альтернативы: только NuGet; централизованный сервис без git.
Последствия: нужны валидатор реестра и клиент журнала сумм.

## ADR-14 — Кэш Roslyn, изоляция ALC, включение в NativeAOT
Дата: 2026-11-18. Обоснование: горячая перезагрузка и автономный исполняемый файл.
Альтернативы: загрузка в общий контекст; только бинарная распространяемая сборка.
Последствия: контракты SDK в общем контексте, реализации в коллектируемом.

## ADR-15 — Атрибут чистоты как условие cross-package fusion
Дата: 2026-11-18. Обоснование: безопасное сплавление через границы библиотек.
Альтернативы: запрет fusion для внешних функций; автоматический анализ чистоты.
Последствия: без атрибута функция становится барьером сплавления.

## ADR-16 — Доверие: подписи, аудит, yank, зеркала
Дата: 2026-11-18. Обоснование: контроль цепочки поставок в академической среде.
Альтернативы: доверие по умолчанию; удаление версий вместо отзыва.
Последствия: замок продолжает работать после yank; нужны приватные зеркала.
